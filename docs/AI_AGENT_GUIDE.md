# AI_AGENT_GUIDE.md

# AI Agent Development Guide

## MiMo Web Toolkit

Версия: 1.0

---

# Назначение документа

Этот документ определяет правила работы AI-агентов с проектом **MiMo Web Toolkit**.

Он предназначен для:

* Xiaomi MiMo Code;
* ChatGPT;
* Claude Code;
* Gemini CLI;
* других AI-инструментов разработки.

Цель документа — обеспечить предсказуемую, качественную и безопасную разработку проекта с использованием искусственного интеллекта.

---

# Главный принцип

AI-агент является не генератором кода, а членом команды разработки.

Перед внесением изменений агент обязан:

1. понять архитектуру;
2. изучить существующие решения;
3. оценить влияние изменений;
4. предложить оптимальный путь реализации.

---

# Перед началом работы

Перед выполнением любой задачи AI-агент должен изучить:

```
PROJECT_SPEC.md
ARCHITECTURE.md
ROADMAP.md
CODING_STANDARDS.md
CONTRIBUTING.md
```

Если эти документы отсутствуют или противоречат друг другу:

* остановить выполнение;
* описать проблему;
* предложить решение.

---

# Анализ задачи

Перед написанием кода AI-агент должен определить:

* какую проблему решает задача;
* какие компоненты затрагиваются;
* есть ли уже похожая функциональность;
* требуется ли изменение архитектуры;
* нужны ли новые зависимости.

---

# Принцип минимального изменения

AI-агент должен изменять минимальное количество файлов, необходимое для решения задачи.

Запрещается:

* переписывать существующий код без необходимости;
* менять архитектуру ради небольшого улучшения;
* удалять существующую функциональность без объяснения.

---

# Планирование

Для сложных задач AI-агент должен сначала создать план:

Пример:

```
Этап 1:
Создать новый интерфейс ImageProvider.

Этап 2:
Реализовать ComfyUI Provider.

Этап 3:
Добавить тесты.

Этап 4:
Обновить документацию.
```

После утверждения плана выполнять реализацию.

---

# Работа с кодом

AI-агент обязан:

* читать существующий код перед изменением;
* соблюдать текущий стиль проекта;
* использовать существующие абстракции;
* не создавать дублирующие решения.

---

# Работа с новыми файлами

Перед созданием нового файла необходимо определить:

* зачем он нужен;
* почему нельзя использовать существующий;
* к какому компоненту архитектуры он относится.

---

# Работа со структурой проекта

Перед созданием новых файлов AI-агент обязан проверить существующую структуру.

Перед созданием новых файлов AI-агент обязан проверить:

docs/PROJECT_STRUCTURE.md

Если требуется новая директория или изменение структуры:
- объяснить причину;
- обновить PROJECT_STRUCTURE.md;
- проверить влияние на ARCHITECTURE.md.

Новые каталоги не должны создаваться без объяснения причины.

Изменение структуры проекта требует обновления ARCHITECTURE.md.

---

# Работа с MCP Tools

При создании нового MCP Tool необходимо определить:

## Название

Например:

```
generate_image
```

## Назначение

Одно предложение, описывающее функцию.

## Входные данные

Строго определённая схема.

Пример:

```json
{
  "purpose": "hero",
  "subject": "modern office",
  "filename": "hero.webp"
}
```

## Выходные данные

Структурированный результат.

Пример:

```json
{
  "success": true,
  "file": "assets/hero.webp"
}
```

---

# Работа с ошибками

AI-агент не должен скрывать ошибки.

При возникновении проблемы:

1. определить причину;
2. создать понятное сообщение;
3. добавить логирование;
4. предложить решение.

---

# Работа с большими изменениями

Если изменение затрагивает:

* более 5 файлов;
* архитектуру;
* публичные интерфейсы;
* структуру проекта;

AI-агент обязан сначала предоставить план.

---

# Работа с документацией

После изменения архитектуры необходимо обновлять:

* ARCHITECTURE.md

После изменения возможностей:

* PROJECT_SPEC.md

После изменения этапов:

* ROADMAP.md

После изменения правил разработки:

* CODING_STANDARDS.md

---

# Формат ответа AI-агента

При выполнении разработки ответ должен иметь структуру:

## 1. Анализ

Краткое описание задачи.

## 2. Архитектурное решение

Почему выбран именно такой подход.

## 3. Изменения

Какие файлы будут созданы или изменены.

## 4. Реализация

Полный код файлов.

## 5. Проверка

Что проверено.

## 6. Следующий шаг

Что делать дальше.

---

# Запрещённые действия

AI-агенту запрещается:

* выдавать неполный код;
* заменять код псевдокодом;
* скрывать ошибки;
* удалять файлы без объяснения;
* менять архитектуру без предупреждения;
* добавлять зависимости без причины;
* создавать временные решения без описания.

---

# Работа с неизвестными требованиями

Если отсутствует важная информация:

AI-агент должен:

1. определить, действительно ли нужна информация;
2. задать минимальное количество вопросов;
3. предложить варианты решения.

Не следует задавать вопросы, если можно сделать разумное предположение.

---

# Приоритеты принятия решений

При конфликте требований порядок приоритетов:

1. Безопасность данных.
2. Стабильность проекта.
3. Архитектурная целостность.
4. Расширяемость.
5. Производительность.
6. Скорость разработки.

---

# Самопроверка перед завершением задачи

Перед завершением работы AI-агент должен проверить:

* соответствует ли код архитектуре;
* нет ли дублирования;
* обновлена ли документация;
* корректно ли обработаны ошибки;
* не нарушены ли существующие интерфейсы.

---

# Цель

AI-агент должен помогать создавать профессиональный программный продукт, а не просто генерировать код.

Главная задача — поддерживать качество, архитектуру и долгосрочную развиваемость проекта **MiMo Web Toolkit**.
