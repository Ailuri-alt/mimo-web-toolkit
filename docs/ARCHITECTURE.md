# MiMo Web Toolkit

**Architecture Document**

Версия: 1.0

---

# Назначение

Данный документ описывает архитектуру проекта **MiMo Web Toolkit**.

Он является основным источником информации о структуре системы, взаимодействии компонентов и принципах построения проекта.

Все архитектурные решения должны соответствовать данному документу.

---

# Цель системы

MiMo Web Toolkit предоставляет Xiaomi MiMo Code набор MCP-инструментов, позволяющих автоматически выполнять задачи, связанные с генерацией и обработкой изображений при разработке веб-сайтов.

Главная цель — сделать генерацию изображений полностью прозрачной для пользователя.

Пользователь описывает задачу.

MiMo самостоятельно принимает решение о необходимости генерации изображений и вызывает соответствующий MCP Tool.

# Основные компоненты

## 1. MCP Server

Ядро проекта.

Отвечает за:

* регистрацию MCP-инструментов;
* обработку запросов от MiMo Code;
* маршрутизацию запросов;
* возврат результатов.

MCP Server не содержит бизнес-логики генерации изображений.

Его задача — координация.

---

## 2. Tool Registry

Отвечает за регистрацию инструментов.

Каждый инструмент должен быть независимым модулем.

Регистрация должна происходить автоматически при запуске сервера.

---

## 3. Prompt Engine

Назначение:

превращение высокоуровневых параметров

например

* Hero Banner
* Product
* Logo

в полноценные профессиональные prompt'ы.

Prompt Engine не содержит информации о workflow.

---

## 4. Workflow Engine

Назначение:

выбор подходящего workflow ComfyUI.

Вход:

* purpose;
* style;
* aspect ratio.

Выход:

JSON Workflow.

---

## 5. Configuration Manager

Отвечает за:

* загрузку YAML;
* проверку конфигурации;
* предоставление настроек другим компонентам.

Все настройки проходят через этот компонент.

---

## 6. ComfyUI Client

Единственная точка взаимодействия с ComfyUI.

Отвечает за:

* отправку workflow;
* ожидание результата;
* получение изображения;
* обработку ошибок;
* контроль времени ожидания.

Другие компоненты не должны выполнять HTTP-запросы к ComfyUI напрямую.

---

## 7. Provider Layer

Отвечает за взаимодействие с конкретной моделью генерации изображений.

Provider скрывает:

* название модели;
* формат файлов;
* параметры запуска;
* особенности VRAM;
* специальные настройки.

**Правило:** Provider никогда не выполняет HTTP-запросы.

Вся коммуникация с ComfyUI осуществляется через `comfy_client.py`.

Направление зависимостей:

```text
Tools → Services → Providers → Comfy Client → HTTP → ComfyUI
```

Обратные зависимости запрещены.

---

## 8. Image Optimizer (ImageProcessor)

Локальная обработка изображений через Pillow. Не выполняет HTTP-запросы.

Отвечает за:

* проверку файла;
* оптимизацию формата (WebP/PNG/JPG);
* конвертацию форматов;
* масштабирование изображений (resize через LANCZOS-интерполяцию);
* сохранение результата;
* предоставление метаданных изображения.

Методы:

* process() — конвертация формата и оптимизация;
* resize() — масштабирование с сохранением качества;
* get_info() — чтение метаданных.

Не отвечает за AI-upscaling — это выходит за рамки v1.0.

---

## 9. Logging System

Все компоненты используют единую систему логирования.

Каждый модуль получает собственный именованный логгер.

---

## 10. Exceptions

Используются специализированные исключения.

Например:

* WorkflowError
* PromptError
* ComfyConnectionError
* ImageGenerationError

# Поток выполнения

Типовой сценарий:

1. Пользователь просит создать сайт.
2. MiMo анализирует задачу.
3. MiMo вызывает MCP Tool.
4. MCP Server принимает запрос.
5. Tool формирует объект запроса.
6. Prompt Engine выбирает шаблон.
7. Workflow Engine выбирает workflow.
8. ComfyUI Client запускает генерацию.
9. Image Optimizer обрабатывает результат.
10. Tool возвращает путь к файлу.
11. MiMo вставляет изображение в HTML.

# Принципы взаимодействия

Каждый компонент имеет единственную область ответственности.

Компоненты взаимодействуют через публичные интерфейсы.

Запрещается обращаться к внутренним деталям другого компонента.

---

# Расширяемость

Архитектура должна позволять:

* добавлять новые MCP-инструменты;
* подключать новые модели генерации изображений;
* заменять ComfyUI на другую систему;
* добавлять новые движки обработки изображений;
* расширять конфигурацию без изменения существующего кода.

---

# Отказоустойчивость

Каждый компонент обязан:

* корректно обрабатывать ошибки;
* логировать исключения;
* возвращать понятные сообщения;
* не приводить к аварийному завершению процесса при локальной ошибке.

---

# Производительность

При проектировании учитывать:

* минимизацию лишних операций ввода-вывода;
* повторное использование конфигурации;
* кэширование неизменяемых данных (например, шаблонов и workflow);
* возможность асинхронного выполнения длительных операций, если это не усложняет архитектуру без необходимости.

---

# Принципы развития проекта

Новые возможности должны добавляться через расширение существующих интерфейсов, а не путём изменения уже работающих компонентов.

Каждое архитектурное изменение должно сопровождаться обновлением данного документа.

---

# Конечная цель

Получить надёжную, расширяемую и хорошо документированную систему, в которой MiMo Code сможет автоматически использовать локальные инструменты генерации изображений при создании современных веб-приложений без изменения собственной логики.
