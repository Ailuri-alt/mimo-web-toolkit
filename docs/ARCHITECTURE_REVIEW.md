# Решения по замечаниям

---

## AR-001

### Тема

Структура `mcp_server/`

### Решение

**Принято полностью.**

Главной структурой проекта считается структура, описанная в `PROJECT_STRUCTURE.md`.

Документ `ARCHITECTURE.md` должен быть приведён в соответствие с ней.

Архитектура `MODEL_PROVIDERS.md` интегрируется внутрь каталога `services/`.

Итоговая структура должна выглядеть следующим образом:

```text
mcp_server/

    server.py
    registry.py
    config_manager.py
    logger.py
    exceptions.py

    tools/

    services/

        providers/

        comfy/

        prompt_engine.py
        workflow_engine.py
        image_processor.py
        queue_manager.py

    models/
```

Приоритет:

**Критический.**

---

## AR-002

### Тема

`config.py` против `config_manager.py`

### Решение

**Принято полностью.**

Во всех документах используется единое название:

```
config_manager.py
```

Причина:

модуль отвечает не только за хранение настроек, но и за их загрузку, проверку и управление.

---

## AR-003

### Тема

Provider Layer и ComfyUI Client

### Решение

**Принято с дополнением.**

Устанавливается архитектурное правило:

**Provider никогда не выполняет HTTP-запросы.**

Вся коммуникация с ComfyUI осуществляется исключительно через `comfy_client.py`.

Архитектурная схема:

```text
Tool

↓

Service

↓

Provider

↓

Comfy Client

↓

HTTP

↓

ComfyUI
```

Все остальные варианты взаимодействия считаются нарушением архитектуры.

Приоритет:

**Критический.**

2. Provider Layer

## AR-005

### Тема

`exceptions.py`

### Решение

**Принято с уточнением.**

На текущем этапе проекта используется один файл:

```
exceptions.py
```

При увеличении количества исключений допускается рефакторинг в пакет:

```
exceptions/
```

без изменения публичного API проекта.

---

### Тема

queue_manager.py

### Решение

**Принято полностью.**

* в ARCHITECTURE.md;

## AR-007

### Тема

HTTP-библиотеки

### Решение

**Отложено.**

Вопрос выбора между:

* httpx
* requests
* aiohttp

не влияет на текущую архитектуру.

Окончательное решение принимается после реализации первого ComfyUI Client.

До этого момента требования не изменяются.

---

## AR-008

### Тема

settings.yaml

### Решение

**Принято полностью.**

Конфигурация должна быть расширена.

Минимально требуется добавить:

* host
* port
* timeout

для подключения к ComfyUI.

---

## AR-009

### Тема

registry.py

### Решение

**Принято с изменением.**

Для устранения неоднозначности рекомендуется использовать:

```
provider_registry.py
```

вместо

```
registry.py
```

в каталоге Provider Layer.

Это уменьшает вероятность путаницы между регистрацией MCP Tools и регистрацией Provider.

### Решение

## AR-013

### Направление зависимостей

Устанавливается обязательное правило зависимостей.

Допустимое направление:

```text
Tools

↓

Services

↓

Providers

↓

Comfy Client

↓

HTTP

↓

ComfyUI
```

Обратные зависимости запрещены.

Provider не должен зависеть от Tool.

Comfy Client не должен знать о Provider.

MCP Tools не должны обращаться напрямую к ComfyUI.
